# Express consent starting point

Generated by Gate-Keeper {{version}} (P3-06, F-005, UC-003). This helper applies only to processing whose lawful basis is consent.

Use the host application's `@inveniotech/gate-keeper` package and TypeScript build. Create one store for the application, with an injected clock, and expose the helper through Express locals:

```typescript
import { ConsentCheck } from '@inveniotech/gate-keeper';
import { EventConsentProvider } from './consent/consent-provider.js';

const provider = new EventConsentProvider(applicationClock);
const check = new ConsentCheck(provider, diagnostic => {
  // Route only the safe purpose/type diagnostic to your logger.
});
app.locals.consentProvider = provider;
app.locals.consentCheck = check;
```

`applicationClock` is the host's `() => Date` clock; use a fixed date in tests. In an existing authenticated handler, await `provider.record(subjectId, purpose, granted, channel, noticeVersion, signal)`. Pass `true` to grant and `false` to withdraw through the same flow. Use `await check.isGranted(subjectId, purpose, signal)` at the processing boundary. Only granted permits consent-based processing.

The store appends `granted` and `withdrawn` events with the subject identifier, namespaced purpose, UTC time, channel and notice version. The latest appended event for that subject and purpose determines current state; no record means denied. `history()` returns a separate array of immutable events. Verify grant, withdrawal, re-grant and separation between subjects and purposes with a fixed clock.

This store is an in-memory example: restarting the application loses every event, and different processes have separate histories. Replace it with application-owned durable, concurrency-safe storage before deployment. Keep the append-only ordering and all event fields. Authorise each request against the authenticated subject, validate input and the notice/channel against application policy, and protect history access. Do not log subject identifiers or history. The scaffold installs no routes, user interface, database or dependencies and edits no existing application files. Wire granting and withdrawal into the application's existing authenticated flow.
