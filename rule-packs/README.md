# Rule packs

This folder holds the bundled rule packs shipped with each release. A rule pack is data, not code: detection logic lives here as JSON with a citation and corpus cases, never in the engine (rule 9 of `AGENTS.md`).

P2-03 now supplies unsigned detection source packs for release assembly. These files are not yet embedded in the CLI or signed for production. Each pack is validated against the rule-pack JSON Schema before it ships. The [draft authoring guide](AUTHORING.md) and [synthetic local template](templates/local.pack.json) demonstrate the existing contract; the template is not shipped as a detection rule. Its real-CLI acceptance tests run with `dotnet test tests/Corpus.Tests -c Release --filter FullyQualifiedName~RuleAuthoringTests`. This module adds no dependency.

The owner approved the current [citation register](CITATIONS.md) and its [JSON data](citations.json) in principle on 5 November 2026. Legal counsel's review remains pending and the owner will introduce any recommended changes. The register is metadata, not a bundled pack. Run `node --test ci/rule-packs/citations.test.mjs` for completeness and approval-aware lookup checks; no new dependency is added.

Run `node ci/rule-packs/build-detection.mjs --write` to regenerate source packs, reference pages and additional synthetic cases; use `--check` to verify exact bytes. Authoring inputs live in `ci/rule-packs/rules/`; do not hand-edit their generated outputs. The [BVN reference](../docs-data/rules/bvn.md) documents its context window, exclusions and limitations. The existing assembly producer combines these source packs with explicit release metadata. Tests sign only in memory with the labelled development key and pass the exact bytes through the real loader and corpus scanner.

The authored set includes [BVN](../docs-data/rules/bvn.md), [NIN](../docs-data/rules/nin.md), [phone](../docs-data/rules/phone.md) and [processor catalogue data](../docs-data/rules/processors.md). Catalogue rules retain processor categories and region metadata at note severity. The current results format exposes identifiers and citations; user-facing processor metadata requires the separate output-contract work under #64. Regenerate the [synthetic measurements](../docs-data/synthetic-measurements.md) after changes with `./ci/rule-packs/Measure-Detection.ps1 -WriteReport`.
